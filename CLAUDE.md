Skills in `misc/`, `in-progress/`, and `deprecated/` must not appear in either.

## Third-party skill suites

`crates/` holds the skill suites this plugin ships. `crates/skillset/glass/` is Glass's own workspace, retaining `workon` and the plugin release version and changelog. `crates/skillset/mattpocock`, `crates/skillset/gstack`, and `crates/skillset/impeccable` are git submodules tracking upstream `main`, declared in `.gitmodules`; nothing under them is edited here. After cloning, run `git submodule update --init`. To upgrade, run `git submodule update --remote`, then `bun run agents` and `bun run link-skills`, re-sync the manifest, and commit the new gitlinks. CI checks out with `submodules: true`. A gitlink pins a commit; `main` is the branch used for remote updates.

### mattpocock

[mattpocock/skills](https://github.com/mattpocock/skills) is the submodule at `crates/skillset/mattpocock`. The manifest ships its `skills/engineering/` and `skills/productivity/` entries. Local discovery links every bucket under `skills/`, alongside Glass's own skills. Preserve upstream invocation metadata, including user-only skills. The previous Glass-specific invocation changes are not applied to this submodule. Its package is not a Bun workspace: release tooling must never version the upstream checkout.

Known cost: Claude Code plugin installs and the Devin plugin loader fetch the repository without submodules, so an installed plugin only sees the submodule content when its installer resolves submodules. Devin also reads a `triggers` key in `SKILL.md` frontmatter as the skill's invocation policy (it expects `model` and `user`), and upstream gstack skills carry a `triggers` list of example phrases, so Devin hides them. Both were accepted when the vendored copies were replaced by submodules; if either bites, the fix is upstream or a generated copy, never an edit inside a submodule.

### gstack

[garrytan/gstack](https://github.com/garrytan/gstack) is the submodule at `crates/skillset/gstack`. `.claude-plugin/plugin.json` lists `./crates/skillset/gstack` (its router skill) and every `./crates/skillset/gstack/<name>` directory that holds a `SKILL.md` (not the `connect-chrome` symlink alias), and `bun run check` requires that list to match the tree exactly.

`agents/*.md` are subagent profiles generated by `scripts/agents.ts` and listed in `plugin.json`'s `agents` array. From `crates/skillset/gstack/review/specialists/*.md` it renders one `<name>-reviewer` per checklist (the description map lives in the script; the checklist text is gstack's verbatim, so the no-em-dash rule below does not apply to those copied sections). Never edit the generated files by hand: change the script or update the submodule, then run `bun run agents`. `bun run check` fails when they are stale.

Every agent profile must load in both Claude Code and Devin, whose [custom subagent format](https://docs.devinenterprise.com/cli/subagents#custom-subagents) is the stricter one: frontmatter holds only `name`, `description`, and `tools` as a YAML list (no `model`, `effort`, or `maxTurns`). `bun run check` enforces this.

gstack skills are not linked into `.devin/skills`, are not routed by `ask-matt` (gstack ships its own `/gstack` router), and get no docs page. Their `SKILL.md` files expect gstack's `./setup` to have installed `~/.claude/skills/gstack/bin`; without it they run in gstack's documented degraded mode.

### impeccable

[pbakaus/impeccable](https://github.com/pbakaus/impeccable) is the submodule at `crates/skillset/impeccable`. It ships a real Claude plugin under `plugin/`, and the manifest points straight into it for the skill: `./crates/skillset/impeccable/plugin/skills/impeccable`. Its four agents under `crates/skillset/impeccable/plugin/agents/*.md` carry `model`, `effort`, `maxTurns`, and a comma-separated `tools` string, which Devin rejects, so `scripts/agents.ts` writes a trimmed copy of each into `agents/` (same filename, frontmatter reduced to the shared format above) and the manifest lists those copies. Upstream's `hooks/hooks.json` and nested `.claude-plugin/` are not shipped. Always point at upstream `plugin/`, never `.claude/` (that copy hard-codes `.claude/skills/impeccable/scripts` paths).

Each owned bucket folder has a `README.md` listing every skill with a one-line description and a link to its `SKILL.md`. The top-level `README.md` groups entries by their actual invocation policy. Upstream bucket READMEs remain unmodified.

Glass skills in promoted buckets have a human-facing page at `docs/<bucket>/<skill-name>.md`. When changing one, re-sync its page following [.agents/writing-docs.md](./.agents/writing-docs.md). For upstream skills, `crates/skillset/mattpocock/docs/` and the upstream skill source are authoritative; the root docs retain the earlier Glass fork's descriptions. Non-promoted skills get no docs page.

Glass-owned skills are model-invoked and user-reachable. Upstream skills retain their own invocation policies. See [.agents/invocation.md](./.agents/invocation.md).

[`ask-matt`](./crates/skillset/mattpocock/skills/engineering/ask-matt/SKILL.md) routes the upstream suite. It is maintained upstream; record Glass-specific routes in this repo's README rather than editing the submodule.

All Glass and Matt Pocock buckets are available through relative symlinks in `.devin/skills`, with `.agents/skills` and `.claude/skills` pointing there. After changing the skill inventory, run `bun run link-skills` and include link changes with source changes or the new gitlink. `bun run check` validates links and Glass invocation metadata. Edit owned sources under `crates/skillset/glass/`. The older `scripts/link-skills.sh` changes global installations; it is not the repository-local setup.

No em-dashes anywhere in this repo's prose (`SKILL.md` files, docs, `README.md`, `CHANGELOG.md`, ADRs, changesets, code comments). Where a sentence reaches for one, rewrite it instead with a comma, colon, period, parentheses, or a conjunction, whichever the sentence actually wants; never do a blind character substitution.

## Monorepo tooling

Use Bun for dependency installation and scripts. Run `bun run check` to verify formatting, lint, TypeScript, builds, tests, and promoted-skill manifest entries. Run `bun run check-plugin-version` separately before releasing.

The root package orchestrates workspaces. `crates/skillset/glass/package.json` owns the plugin release version under the `glass-skills` package name so existing changesets still resolve. Release tooling lives in the private `@glass/scripts` workspace. New applications and libraries go under `apps/*` and `packages/*`; their TypeScript configs extend the root `tsconfig.json`.

### Skill index

`crates/skillset/skillset/skills.csv` is the reviewed pick list for the plugin: one row per skill found under `crates/skillset/<suite>/` (every suite except `skillset` itself, skipping dot-directories, `node_modules`, and `test`/`tests`/`fixtures` paths, and symlink aliases). `bun run index-skills` regenerates it; the `@glass/skillset` workspace's `check` script runs the same indexer with `--check`, so `bun run check` fails when the csv is stale (after a submodule bump, run `bun run index-skills` and commit the result). Columns, sorted by `path`:

- Script-owned, rewritten every run: `path` (relative to `crates/skillset/`), `category` (the skill directory's parent folder, or the suite name when the parent is the suite root or a folder named `skills`), `name` (frontmatter `name`, else the directory name), `description`, and `url` (frontmatter `url` or `homepage`, else a per-suite rule: mattpocock skills with an upstream docs page link to `https://aihero.dev/skills-<name>`, Glass skills with a `docs/<category>/<name>.md` page link to it on GitHub, impeccable links to `https://impeccable.style`, gstack has no page).
- Human-owned, preserved verbatim: `new_category` and `new_name` (blank means unchanged) and `status` once it is `picked` or `skipped`. The script sets `new` for a skill not yet in the csv (or one that came back after being `deleted`) and `deleted` for a row whose skill is gone from disk; delete those rows by hand once you have seen them. `new` rows are allowed by `check`: reviewing is a human step.

Only `picked` rows are meant to ship; why the set is curated this way is in [docs/adr/0003-curate-shipped-skills-with-skills-csv.md](./docs/adr/0003-curate-shipped-skills-with-skills-csv.md).

Markdown files are importable. Bun's default `md` loader renders them to HTML, so add `with { type: "text" }` to get the raw Markdown string: `import readme from "../README.md" with { type: "text" };`. Either way the import is a `string`, typed by `types/markdown.d.ts`, which the root `tsconfig.json` includes for every workspace. See `scripts/markdown-import.test.ts`.
